# Object-snapshot collector protocol

Frozen 2026-11-17 before implementation. This research prototype reads one schema-2 ledger and a named Git commit, runs the fixed installed `review-ledger next` on a temporary byte-identical copy, and returns a shadow observation. It never starts a review, modifies a subject repository, authorizes execution, claims approval, or changes policy.

The only executable policy is `/home/mini/.agents/skills/build-loop/scripts/review-ledger`, SHA256 `7a3d78806ee6750cfa9efa04cee06610e3b0315f29b723f6a232b61903ab5920`. The collector pins its bytes before and after canonical invocation. It also rechecks source ledger bytes afterward. Supplied `capture_verified` fields have no authority. Unknown policy output, unsupported script bytes, malformed ledgers, changed sources, and failed subprocesses return explicit insufficient evidence.

`capture --source-root ROOT --ledger FILE --repo DIR [--revision FULLSHA] [--fact FILE] [--store DIR]` confines source paths to the explicit root, rejects symlinks, limits ledger to 1 MiB, fact to 64 KiB, and source artifact to 256 KiB. Default revision resolves HEAD. Explicit revisions are full 40- or 64-digit commit IDs. Git commands are read-only, with fsmonitor disabled and no external diff/textconv. The snapshot is Git objects only, identified by commit, tree ID, and tree-object SHA256. Dirty working-tree code is outside coverage and is never reported reviewed. Latest current-phase ledger round must resolve exactly to the named commit before any optional-boundary candidate. Parent-verified final fixes are unsupported.

A supplied trigger fact is an assertion with category, accepted Boolean, fix commit, canonical diff SHA256, source artifact path, and source artifact SHA256. Supported categories are asynchronous waits, locks/leases, cancellation, transaction publication, and multi-stage transitions. Verify the fix is a single-parent ancestor of the named commit and hash `git diff --binary --full-index --no-renames --no-ext-diff --no-textconv PARENT FIX --` with pinned formatting flags. Artifact bytes must match. Acceptance is supplied evidence of an accepted fix, never proof of a defect or a calibrated model output.

Canonical ARGUE/ROUND/CHECKPOINT/OWNER-OK/NIT-CULL/FIX-KEPT/STEP-BACK means required work remains. STOP-STUCK means escalate with its precise reason. Only STOP-AGREED on matching object coverage can produce a shadow candidate. No trigger means insufficient evidence, never early stop. Tier-2 count at its cap and tier-1 phase count at its cap prevent an extra candidate and require escalation. There is no generic optional slot: every output sets `execution_allowed=false` and `allocation=unresolved`.

If `--store` is given, snapshots are written as new content-addressed JSON files under this prototype directory only; existing files are checked byte-for-byte and never overwritten. `record-outcome --observation FILE --outcome FILE --store DIR` appends a separately addressed outcome linked to the observation hash. Unknown outcomes remain explicitly unobserved. Records contain no producer authenticity claim; conflicting observations or outcomes stay separate and visible. No mutable registry is maintained.

Trusted boundaries are the current user, installed policy, Git binary, explicitly selected local repository metadata, and research output directory. This is not a hostile multi-user filesystem service. No repository-provided program, Git hook, checkout, build, or reviewer executes. Source reads use no-follow file descriptors and inode/metadata rechecks. Subprocess time and output sizes are bounded. Paths and reviewer text are data. Secrets are not printed except content deliberately supplied in the bounded ledger/fact fields used for explanations. Stored records contain source hashes and selected facts, not full source file contents.

Before implementation, meaningful CLI tests must fail for missing collector, then cover real canonical policy pass/pending/cap results, exact snapshot refusal, supplied verification-field impotence, trigger ancestry/diff/artifact checks, source confinement, immutable storage, and separate outcome unknowns. Three isolated mutations must be caught: bypass exact snapshot matching, bypass confinement, and map a required gate to an optional candidate. Synthetic Git fixtures are created only in temporary directories under this prototype. One real historical object-only capture is a smoke test, not an as-of optional-boundary label.
