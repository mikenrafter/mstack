## Decisions to review

- cancel.json is written after cancel reads the qex status, not before. Before would leave the T5 window (cancel read state, then cancel.json) with no await point to test; after it, a status can still move the job between cancel's read and its write, which is exactly the case the id guard and the cancel's second round cover.

- T7: the cancelled/never-ran outcome is also inside the try, so a storage error while writing the log of a cancelled job ends it `failed` with the import diagnostic, not cancelled.
- finish's early `cancelRequested` read stays outside the lease; finishExport's re-read covers the window.
