# test-quality reference: valuable test shapes

The positive counterpart to `modes.md` (owner, 2026-11-27): shapes that catch bugs a plain example
test with a small or unrealistic fixture misses. Each shape names the bug class, when it pays, how the
shape itself goes hollow, and a public exemplar. "Verified" means the cited source was read; "Inferred"
marks design advice and predicted failures. Private-repo exemplars and the fixture-realism measurement
live in `mstack.research/test-shapes/`.

## 1. Metamorphic relation

**Inferred.** Change the input in a way the contract says must preserve or predictably change the result. This pays for streaming, incremental computation, and order-independent queries where hand-calculating every result is expensive. Require the transformation to cross a meaningful boundary. Two output paths can share the same defect, so keep a separate known-answer case.

**Verified.** Dart's digest tests use non-uniform bytes and compare one-shot hashing with two streaming APIs over lengths 0 through 300 and several chunk widths. **Inferred.** A streaming buffer that drops the remainder when a write straddles a block can pass a one-shot check and fail here. [`chunked_conversion_test.dart:30`](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/crypto/test/chunked_conversion_test.dart#L30)

## 2. Generated property with shrinking

**Inferred.** Generate structured inputs, check a claim for every input, and reduce a failing case to a smaller counterexample. Use this when combinations of keys, values, or lengths affect the result and the claim is cheaper to evaluate than a separate expected output. Bias the generator toward the branch that matters and record its firing count. A generator that almost never produces ties, or a property that merely checks the output type, wastes runs.

**Inferred, synthetic.** Generate lists with distinct record IDs and keys drawn from a small shared range. After a stable sort, check sorted keys, exact membership, and the original order within each key. Bias some cases to long equal-key runs. An unstable merge that takes the right element first on ties can pass distinct-key examples. Shrinking can reduce that failure to two equal-key records.

## 3. Stateful model

**Inferred.** Apply a generated command sequence to the real entry point and to a small reference model. Compare observable state and error results after each step. Use it when the same command has different meanings depending on earlier commands. Track which transitions fired. A model copied from the real state machine shares its bugs, and a generator that mostly issues illegal commands learns little about successful transitions.

**Inferred, synthetic.** Model an undoable editor as a list of committed document versions. Generate edits, undos, redos, and an edit after undo. Check the visible document and whether redo is available at every step. A reducer that retains the old redo branch after a new edit passes isolated edit and undo checks.

## 4. Differential test with an independent implementation

**Inferred.** Compare the same inputs against another implementation or a slow reference written directly from the contract. Use it for graph algorithms, numerical kernels, and formats with an independent implementation. Choose a reference with different failure modes. Check its assumptions, compare all contract fields, and pin its version when storing its results.

**Verified.** Dart's digest suite compares padding-edge results with checked-in outputs generated by Python's `hashlib`. This is an offline differential check with a fixed input grid. **Inferred.** A Dart implementation that uses only one final block for a 56-byte message disagrees with the independently generated digest. [`md5_test.dart:65`](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/crypto/test/md5_test.dart#L65), [vector provenance at line 219](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/crypto/test/md5_test.dart#L219)

## 5. Round trip anchored to literal wire data

**Inferred.** Exercise encoding and decoding against externally defined bytes or text and check semantic fields. Add a round trip to cover combinations cheaply. Use this when stored or transmitted values have to work across versions or implementations. A writer and reader can agree on the same wrong field order or escaping rule.

**Verified.** Dart's HTTP media-type tests pin literal serialization for a parameter containing a backslash and one ending with a backslash, then reparse the result. A nearby decoder test independently pins decoded parameter values from literal text. **Inferred.** An encoder that omits escape doubling, or a decoder that preserves both backslashes, fails an anchored assertion. [`media_type_test.dart:165`](https://github.com/dart-lang/http/blob/f6fdb8c8857cee1f1cea2f1a0a5b6e1d7f116bae/pkgs/http_parser/test/media_type_test.dart#L165), [independent decoder case at line 62](https://github.com/dart-lang/http/blob/f6fdb8c8857cee1f1cea2f1a0a5b6e1d7f116bae/pkgs/http_parser/test/media_type_test.dart#L62)

## 6. Recorded replay

**Inferred.** Replay a scrubbed session or production trace through the real parser or adapter and assert the downstream result. Use this when external systems supply combinations, event order, or version quirks that are hard to invent. Record the producer version and where the trace was trimmed. Avoid matching unstable IDs or exact prose unless they are part of the contract. Keep the fixture available in normal test runs.

**Verified.** T3 Code replays a recorded Kiro session in which an unavailable model is accepted initially and rejected at prompt time. It checks the terminal failure, model identifier, explanation, and error code. **Inferred.** A mapper that replaces the provider explanation with a generic failure passes a simpler status-only test. [`KiroAdapterV2.test.ts:1359`](https://github.com/pingdotgg/t3code/blob/d898612a0340ff526fd8d5a2cdfb2935360ba8d4/apps/server/src/orchestration-v2/Adapters/KiroAdapterV2.test.ts#L1359)

## 7. Fault injection and recovery

**Inferred.** Fail a named operation after earlier work has occurred. Check the committed state and visible effects, then retry. If the contract concerns restart, reopen durable state in a new instance or process. Use this for migrations, acknowledgments, and multi-step writes. A fault injected too early can leave nothing to roll back. A clean shutdown can conceal what a real interruption would leave behind.

**Verified.** T3 Code uses a SQLite trigger to abort a migration ledger write. It checks the earlier schema change rolled back, the existing ledger and import row survived, and the migration succeeds on retry. **Inferred.** Committing the schema and recording the ledger in separate transactions leaves an extra table after failure. [`reconcileV2PreviewMigration.test.ts:157`](https://github.com/pingdotgg/t3code/blob/d898612a0340ff526fd8d5a2cdfb2935360ba8d4/apps/server/src/persistence/reconcileV2PreviewMigration.test.ts#L157)

## 8. Controlled concurrency interleaving

**Inferred.** Hold one participant at the disputed step, let the other act, and release the first. Check the surviving identity or final persisted state. Use this where cancellation, ownership, or two writes can overlap. Starting two tasks together leaves the order to the scheduler. A gate upstream of the actual contention can miss the race too.

**Verified.** T3 Code waits until an attachment copy has been requested, interrupts the claim, then lets an actual filesystem copy finish. It checks the copy succeeded, the claim was interrupted, and only the staged file remains. **Inferred.** Cleanup that deletes the destination before the writer finishes lets the late copy recreate it. [`AttachmentClaims.test.ts:202`](https://github.com/pingdotgg/t3code/blob/d898612a0340ff526fd8d5a2cdfb2935360ba8d4/apps/server/src/orchestration-v2/AttachmentClaims.test.ts#L202)

## 9. Boundary table derived from the contract

**Inferred.** Tabulate inputs just below, on, and just above each decision point, with an expected outcome for each. Include duplicate or coincident boundaries when the rule must choose the first or last match. Use this for comparisons, transitions, and quotas. Ten interior cases can still miss an inclusive comparison. Derive expected outcomes from the written rule.

**Verified.** Dart defines lower bound as the first position that does not compare less than the target. The tests check values below and above keys, equality with keys, and repeated matches after a smaller key. **Inferred.** A search returning an arbitrary equal position passes unique-key tests and can fail on duplicates. [`algorithms_test.dart:122`](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/collection/test/algorithms_test.dart#L122), [contract at `algorithms.dart:65`](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/collection/lib/src/algorithms.dart#L65)

## 10. Golden over representative input

**Inferred.** Compare the whole contract output with a checked-in file people can review. Use it when the parts have to fit together, as in a migrated source file, report, or rendering. Cover the important variations in one readable fixture. Pin the environment and normalize only incidental fields. Blind regeneration and hard-to-read diffs can turn an exact assertion into an approval ritual.

**Verified.** Dart's OS detection package runs the real fix tool on dependent source files and compares them with committed expected files. The fixture instructions require reviewing regenerated output. **Inferred.** A fix that rewrites API calls but leaves a stale import or duplicates the replacement import changes the complete source. [`fix_data_test.dart:23`](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/os_detect/test/fix_data_test.dart#L23), [fixture instructions](https://github.com/dart-lang/core/blob/0762ac318188cf0ade513d1c62b02b72b45f6b33/pkgs/os_detect/test_fixes/README.md)

## 11. Integration through the real collaborator

**Inferred.** Drive the production entry point with the actual database, serializer, filesystem, or local service. Use it when the risk lives in the collaborator's semantics, such as transactions, stream finalization, or path handling. Assert the result a caller receives or can read back. A substitute that returns pre-shaped data skips the contract under test. Prefer a disposable local dependency so setup and cleanup stay repeatable.

**Verified.** Dart's HTTP package writes a file to a temporary directory, adds it through the public multipart API, and checks the finalized body including disposition, filename, body text, and terminating boundary. **Inferred.** An implementation that sends the full source path as the filename fails even if its mocked file reader reports the right content. [`multipart_test.dart:23`](https://github.com/dart-lang/http/blob/f6fdb8c8857cee1f1cea2f1a0a5b6e1d7f116bae/pkgs/http/test/io/multipart_test.dart#L23), [finalization at `utils.dart:91`](https://github.com/dart-lang/http/blob/f6fdb8c8857cee1f1cea2f1a0a5b6e1d7f116bae/pkgs/http/test/utils.dart#L91)

## 12. Negative space

**Inferred.** Start with something accepted and make one forbidden change at a time. Check the rejection category and, when relevant, show that the rejected operation left state unchanged. Use this for validators, parsers, and transitions with forbidden inputs. An assertion that accepts any error can pass because setup was broken. Several simultaneous violations can hide a missing check.

**Verified.** Dart's media-type suite checks that `type`, `subtype`, and `mimeType` each work on their own. It then checks that `mimeType` combined with either component raises an argument error. **Inferred.** A method that silently gives `mimeType` precedence would pass all three single-argument tests. [`media_type_test.dart:98`](https://github.com/dart-lang/http/blob/f6fdb8c8857cee1f1cea2f1a0a5b6e1d7f116bae/pkgs/http_parser/test/media_type_test.dart#L98), [refusals at line 128](https://github.com/dart-lang/http/blob/f6fdb8c8857cee1f1cea2f1a0a5b6e1d7f116bae/pkgs/http_parser/test/media_type_test.dart#L128)

## 13. Resource budget under load

**Inferred.** Exercise a workload large enough to exhaust the old approach. Assert a resource ceiling and show that useful work still happened. Use bytes, rows, calls, or allocations when those directly represent the contract. For elapsed time, choose an environment and tolerance that distinguish the regression from ordinary variability. A tiny workload cannot reveal growth, and a test that measures without enforcing a ceiling is a report.

**Verified.** T3 Code drives its HTTP and WebSocket handlers with synthetic history and megabyte-scale tool output. It checks that the large result is still stored, checks projected content, and fails when transfer measurements exceed configured ceilings. **Inferred.** A projection that sends every full tool result can preserve correctness while breaking the transfer budget. [`transferBudgetV2.integration.test.ts:316`](https://github.com/pingdotgg/t3code/blob/d898612a0340ff526fd8d5a2cdfb2935360ba8d4/apps/server/integration/transferBudgetV2.integration.test.ts#L316), [ceiling comparison at `TransferBudgetReport.integration.ts:408`](https://github.com/pingdotgg/t3code/blob/d898612a0340ff526fd8d5a2cdfb2935360ba8d4/apps/server/integration/TransferBudgetReport.integration.ts#L408)

## Choose by what can go wrong

**Inferred.** Match the test to the observed risk in the code.

| Code clue | First test to consider |
| --- | --- |
| Same operation has a streaming or incremental entry point | Metamorphic relation, with a separate known answer |
| Combinations of lengths, keys, or values change behavior | Generated property with shrinking |
| Correctness depends on command history | Stateful model |
| Complex computation has a simpler credible reference | Differential test |
| Format outlives the current writer and reader | Anchored round trip |
| The producer supplies surprising event order or fields | Recorded replay |
| State spans several writes or an acknowledgment | Fault injection and recovery |
| Participants can overlap at a lock, write, or cancellation | Controlled interleaving |
| Behavior changes at a written threshold or equality | Boundary table |
| The whole artifact is reviewed or consumed | Golden |
| Correctness depends on the dependency's semantics | Real collaborator |
| The interface forbids specific inputs or transitions | Negative space |
| Work or transfer can grow without changing the answer | Resource budget |

**Inferred.** These are starting points. Use the smallest input that reaches the suspected failure and makes its effect observable.
